    Markdown rendering baseline, Phase 1 — 2026-10-18 (#1044)¶

    The first live run of docs/qa/tests/docs_markdown.md, Phase 1 only (TC-MD001–016, the 16 realistic documents). Per the suite's "Running this suite" step 6, Phase 1's failures are filed before Phase 2 starts.

    Result: 0 of 128 case × entry-point cells pass. Each of the 16 documents went through all 8 entry points, twice (Run 1, Run 2). 125 cells rendered identically in both runs; 3 (EP-8 of TC-MD004, TC-MD011, TC-MD013) changed between runs, which fails Rule 4 on its own.

    Setup¶

    • Code under test: develop at 504a5b2b. The four servers used all run from the main checkout, whose src/, pyproject.toml and uv.lock matched develop exactly. LOCAL_FILE_ACCESS was the stdio default, full.
    • Servers (one shard each): mcp-gee-sweet-kai-oauth (A), mcp-gee-sweet-oauth (B), mcp-gee-sweet-kai-sa (C), mcp-gee-sweet-sa (D). Two OAuth and two service-account identities, all writing to the fixture Shared Drive. The lane servers weren't used: lanes A and B were mid-ticket (#1057, #1056).
    • Shards: A: TC-MD001/005/009/013; B: 002/006/010/014; C: 003/007/011/015; D: 004/008/012/016. Same assignment in both runs.
    • Folders: QA-MD-2026-10-18-run1 and -run2 under TEST_FOLDER_ID, each with one subfolder per shard holding that shard's ep5/ep6/ep7 children. Trashed after recording.
    • Playwright: verified signed into the fixture-owning account before spawning (fixture doc title matched). One 1400×2200 viewport showed each whole Doc (one or two pages), so each cell has one JPEG screenshot, docs/qa/screenshots/md/run<N>/EP-<n>/<TC>-1.jpeg (gitignored, kept until the issues below are fixed).
    • Determinism check: every Run 2 screenshot was pixel-compared with its Run 1 pair (grayscale, threshold 40, Docs chrome and text caret masked). 96 pairs: 0 changed pixels. 29 pairs: 3–9 scattered JPEG pixels. 3 pairs: 3,174–11,141 pixels, all in an EP-8 code block (below).

    Nondeterminism (EP-8)¶

    The same fixture rendered through upload_file(source_format="markdown", convert_to_doc=True) sets its fenced code blocks in a monospace font one time and in Arial the next:

    Fixture Run 1 Run 2 Extra renders
    r04 monospace Arial —
    r11 Arial "Courier" (font box, read in the live Doc) —
    r13 monospace Arial 3 more, all Arial (1 of 5 monospace)
    r03, r16 monospace monospace —

    Each shard re-shot the changed cell after a reload to rule out a font-loading race. get_doc_as_markdown exports the Arial renders without a fence, consistent with the runs not being Courier New. Text, line breaks and indentation were identical across runs. Filed under #1102.

    Findings that weren't filed¶

    • Pagination in Drive-imported Docs (EP-5 to EP-7): tables split with a repeated header row, and a heading moves to the next page with its table. Ordinary Docs pagination, not a rendering defect.
    • Uneven column widths in r11's action-items table (EP-1 to EP-4): auto-sized columns; column widths are #809's territory.
    • Drive's task items render as native Docs checklists rather than ● ☐ text. Equivalent on screen; recorded under #1101 as an engine difference, not as a failure of its own.

    Process notes¶

    • Lock slip (Run 1, shard A): one acquire and a browser_navigate went out in the same parallel batch, so a navigate ran at 15:38:50Z while another shard held the Playwright lock. The screenshots taken around that moment (TC-MD006 EP-1 at 15:38:45Z, TC-MD008 EP-1 at 15:38:57Z) show the right Docs. Run 2's rules required the acquire in its own call before any Playwright call; no recurrence.
    • Aziz's worktree token is a personal Gmail account, not the fixture owner, so it can't read the Shared Drive. The pre-flight in aziz.md checks only that the token refreshes. The mechanical structure diff planned for this run was dropped for the pixel comparison above; structural questions went through get_doc_structure on kai-oauth.
    • Worktree-isolation guard: shards had a few Bash calls refused (shell variables, $((…)), compound commands) and re-ran them as plain commands or scratch scripts. One shard's rm -rf of its own scratch dir was blocked by the safety check; it removed the empty dirs with rmdir. No classifier denials of any approved write.
    • #1052: no connection resets in either run.
