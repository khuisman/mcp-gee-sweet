# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Run locally from the cloned repo:
```bash
uv run mcp-gee-sweet
uv run mcp-gee-sweet --transport sse   # SSE instead of stdio
```

Build and publish:
```bash
uv build       # produces dist/*.whl
uv sync        # install deps from uv.lock
```

Docker:
```bash
docker build -t mcp-gee-sweet .
docker run --rm -p 8000:8000 \
  -e CREDENTIALS_CONFIG=<base64> \
  -e DRIVE_FOLDER_ID=<id> \
  mcp-gee-sweet
```

Tests live in `tests/` and can be run with `uv run pytest`.

## Architecture

Logic is split across `src/mcp_gee_sweet/`: `server.py` (MCP setup, tool decorator, resources), `auth.py` (lifespan, `SpreadsheetContext`), and `tools/` (domain-based layout).

Each entry below says what a module owns and the invariants a future edit could break. The per-PR history behind them (review rounds, reversed approaches, the incident behind each rule) is in [`docs/design/module-history.md`](docs/design/module-history.md), linked from each entry as *History*. Read a module's history before changing its behavior. Record new history in a design or decision doc, not here.

- `tools/sheets/helpers.py` — A1 notation helpers (`_parse_a1_notation`, `_column_index_to_letter`, etc.)
- `tools/drive/files.py` — file/folder operations (`create_spreadsheet`, `import_csv_to_sheet`, `list_spreadsheets`, `list_files`, `search_files`, `create_folder`, `create_shortcut`, `copy_file`, `move_file`, `rename_file`, `star_file`, `unstar_file`, `delete_file`, `restore_file`, `empty_trash`, `list_shared_with_me`, `list_recent_files`, `get_storage_quota`, etc.). `rename_file` and `star_file`/`unstar_file` mark the file's parent folder(s) dirty in `drive_folder_cache`, so a later `list_files` reflects the change without a manual `refresh_cache` (TC-D202/203/260 in `docs/qa/tests/drive_files.md`). `get_file_metadata`/`list_files`/`search_files`/`search_spreadsheets` surface `starred`; `list_files`/`get_file_metadata` surface `md5_checksum` (`None` for Workspace files, which have no fixed bytes) so callers can detect real content drift instead of trusting `modifiedTime`. Every `files().list` passes `includeItemsFromAllDrives`/`supportsAllDrives`. One with no `in parents` clause also passes `_corpora_kwargs(None)` (`corpora="allDrives"`): Drive's default `user` corpus leaves out Shared Drive files the caller never opened, so a service account's unscoped search missed most of them (#1127). Folder-scoped calls keep the default corpus, and so does `list_shared_with_me`, since `sharedWithMe=true` is its scope and the `user` corpus already holds files shared directly with the caller. [History](docs/design/module-history.md#toolsdrivefilespy).
- `tools/drive/sharing.py` — permissions (`share_spreadsheet`, `share_file`, `list_permissions`, `update_permission`, `remove_permission`, `transfer_ownership`). `transfer_ownership` requires OAuth — service accounts have no personal Drive identity to transfer ownership to/from, so Drive's API rejects the transfer.
- `tools/drive/transfer.py` — upload/download/sync/export/revisions. [History](docs/design/module-history.md#toolsdrivetransferpy). Invariants:
  - **A Drive-supplied name reaches a local path only through `_safe_local_dest` (GHSA-hx2f-x3v8-jq2v, CWE-22).** Whoever shares a file controls its name, and a raw `local_path / name` join let `download_file`, `download_folder`, and `sync_folder` write outside `local_path`. Build every local file or directory this module writes for a Drive entry with `_safe_local_dest`: it refuses an unsafe name and backstops with a containment check against the resolved base. Check the name actually written locally (with its export suffix, or a converted Doc's source name read from `properties`), not only `f["name"]`. `sync_folder` also screens names while planning, reporting a refused one as an `unsafe_name` step.
  - `_upload_local_file` (the core of `upload_local_file`) stays module-level: `docs/images.py` imports it cross-package, the same way `docs/content.py` imports `_quota_error_text` from `tools/drive/__init__.py`. Every `storageQuotaExceeded` site renders `_quota_error_text(drive_service)`, which picks `_SA_QUOTA_ERROR` or `_USER_QUOTA_ERROR` from the service's own credentials (#1009). Never return either constant directly: the service-account text misleads a user identity.
  - **Two conversion mechanisms; don't conflate them.** Drive *native import conversion* uploads with the source mimeType and sets the target Workspace mimeType in metadata (`_CONVERT_MIME`: CSV/XLSX→Sheets, DOCX/MD/HTML→Docs, PPTX→Slides). It backs `upload_local_file(convert=)`, `upload_local_folder(convert=)`, `sync_folder(convert_markdown=)`, and `upload_file(convert_to_doc=)` (raw content, always a Doc; shares `_GOOGLE_DOC_MIME`). `docs/content.py`'s `create_doc_from_file` is different: it parses locally and rebuilds via Docs API requests.
  - **Converted `.md` Docs** keep the `.md` name in Drive and are recognized on every later sync by a Drive `properties` marker stamped at creation through `_convert_properties` (by both `_sync_level` and `_upload_local_file(convert=True)`), regardless of the current call's flags. Values must fit Drive's 124-byte per-property cap: `_CONVERT_MARKDOWN_SOURCE_PROP` holds the raw name when it fits, else `_CONVERT_SOURCE_PROP` holds a `sha256:` digest (a digest-marked Doc stops matching if renamed; see `docs/known-limitations.md`). Classify through `_converted_md_source_name`/`_is_converted_md_entry`, recomputed from the resource each time; never cache the classification on a `drive_map` entry. There is no reverse conversion: a drive-only or Drive-edited converted Doc is a `conflict` (message via `_NO_REVERSE_CONVERSION_CLAUSE`), except `direction='upload'`, which reports a plain `skip`.
  - **Name collisions** in `drive_map` (any duplicate name, any type) go through the plan as a `"collision"` action: `conflict` under `dry_run`, a `failed` entry (`kind: "collision_fail"`) on execution. Never write to `failed` from the `drive_map`-building loop.
  - **Local directories are created at the first local write, never up front (#1012).** `download_file` validates `export_format` and fetches an export before its mkdir. `download_folder` creates `local_path` only once it has a file to download. `sync_folder` creates it at a file download (`_run_one`) or a Drive-only subfolder's creation, so a `dry_run`, an upload-only sync, or a call that fails before writing leaves nothing; a missing `local_path` plans as empty. A media download needs its directory before it streams, so a failed one keeps it. Never add an `rmdir` rollback: it can race another call writing into the same new directory (PR #1023).
  - **`dry_run`** never reports failures and never hashes. It leaves `uploaded`/`downloaded`/`skipped`/`conflicts`/`failed` empty; `actions` alone is the complete preview (duplicating it tripped the response cap).
  - **`modifiedTime` stamping.** Every upload stamps `modifiedTime` from the local mtime in `create()`. A converted upload also needs a metadata-only `update()` afterward, because Drive's asynchronous conversion overwrites the create-time value (the doubled latency is accepted). If that restamp fails after `create()` succeeded, report the created file's ID via `_restamp_failure_result` (`{"error", "fileId"}`); `_sync_level`, `upload_local_file`, and `upload_local_folder` must carry `fileId` into `failed` and treat that result as cache-dirtying. `_upload_local_file` catches broadly and returns `{"error": ...}`, since the tool has no try/except of its own. For a converted `.md` Doc the restamp is cosmetic, not load-bearing: the Docs backend updates `modifiedTime` asynchronously, minutes behind, and can overwrite it (#814).
  - **`sync_folder` comparison** for a name on both sides: mtime diff first, against `_SYNC_MTIME_TOLERANCE`. Within tolerance but a different `size` (non-Workspace files only) is a `conflict` for every direction: recency is unknown, so never auto-transfer. `use_checksum=True` hashes every both-sides pair that has a Drive `md5Checksum` (after the plan loop, concurrently, capped by `_SYNC_HASH_CONCURRENCY`, filling placeholder steps from `_mtime_step`): a match is in sync, a within-tolerance mismatch is a `conflict` (`_diverged_same_mtime_step`), and a mismatch outside tolerance falls through to the mtime logic. Under `dry_run` those reasons end in `(checksum not verified in dry_run)`. A local file that can't be read or stat'd becomes a `"local_read_fail"` plan action, never an uncaught raise. Workspace and converted files have no `md5Checksum`/`size` and compare by mtime alone, except a converted `.md` Doc carrying `_CONVERTED_MD_SOURCE_MTIME_PROP` (next bullet).
  - **Converted `.md` change detection (#814).** A converted `.md` Doc carrying `_CONVERTED_MD_SOURCE_MTIME_PROP` never consults `modifiedTime`. Its local side compares against that stamp, and its Drive side against revision history (`_converted_md_drive_state`/`_converted_md_step`, fetched after the plan loop, during `dry_run` too). A Drive edit to such a Doc is always a `conflict`, even when the local file changed too, until a call names it in `sync_folder(resolve=)` (next bullet). A revision-read failure is a `"drive_read_fail"` plan action. Every converted-`.md` upload must stamp through `_converted_md_upload_properties` (source mtime + upload time; with `reupload=True` it also records the baseline revision, read before the `update()`, and clears the import revision). A Doc without the stamp (converted before #814) stays on the mtime path until its next re-upload or a `resolve='keep_drive'`.
  - **`sync_folder(resolve=)` (#860)** turns a converted-`.md` `conflict` into `keep_drive` or `keep_local` without changing the Doc's file ID (`docs/decisions/decision-converted-doc-change-detection.md`). Eligible: a `conflict` on a convert_markdown Doc with a matching local `.md`, whichever detection reported it (pre-#814 Docs included). Every key is checked first against a read-only `dry_run` pass of the whole tree, because a real run executes each level before planning the next. Any ineligible key makes the whole call return `{"error": ...}` with nothing written, so `dry_run` must never write, not even an import revision. A key that turns ineligible by the real pass lands in `failed` and never falls back to its step's planned action. `keep_local` reuses the re-upload path. `keep_drive` records the latest revision as the import revision and stamps the *planned* local mtime, not a fresh stat. If Drive's latest revision moved since planning, it reports `conflict` and changes nothing.
  - **`upload_local_folder`** routes each file through `_upload_local_file(skip_if_exists=False)` but keeps its own single bulk `list()` for `skip_if_exists` (name match; name plus target mimeType when `convert=True`), so existence is checked once. An unsupported extension under `convert` lands in `failed`, never uploads as-is.
  - **`sync_folder(result_local_path=)`** is its response-cap bypass (`local_path` already means the sync directory). It's rejected with `ValueError` before any API call if it resolves inside `local_path`, where the manifest would be synced up. `enforce_response_size_cap(local_path_param=...)` names the right parameter in the cap error.

- `tools/docs/` — Google Docs package; `__init__.py` is a thin dispatcher that delegates to four submodules:
  - `docs/content.py` — helpers (`_md_to_html`, `_to_doc_requests`, `_html_to_doc_requests`) and tools (`create_doc`, `get_doc_content`, `write_doc_content`, `create_doc_from_file`, `update_doc_from_file`, `get_doc_structure`, `find_in_doc`). `_apply_doc_content` is shared by `create_doc`/`create_doc_from_file`/`write_doc_content`; `_replace_doc_content` (clear, then insert, as separate `batchUpdate` calls because of the same-batch `insertText` style-inheritance quirk) by `write_doc_content`/`update_doc_from_file`. `find_in_doc` returns UTF-16 offsets usable directly with `style_doc_range`. `get_doc_structure` surfaces each paragraph's `headingId` and `bullet` (`{listId, nestingLevel}`, a top-level item's absent level normalized to `0`). After conversion, `_has_pending_anchor_links(content_requests, tables)` gates `_resolve_heading_anchors`, which rewrites a `#slug` link to `.../edit?tab=t.0#heading=<headingId>` or strips it when no heading matches confidently: a link to the wrong section is worse than no link (`docs/design/heading-anchor-resolution.md`). Its walker, `_walk_headings_and_anchor_runs`, must recurse into table cells and carry the offset forward when an element has no `startIndex` (the doc's first element often doesn't). Markdown/HTML images go through `_resolve_image_source`: a local path (uploaded), `drive:<file_id>`, or a public `http(s)://` URL. Local and `drive:` sources are shared `anyone:reader` and revoked after embedding unless `revoke_sharing=False`, through `images.ImageShareLifecycle` (below). One unfetchable `insertInlineImage` fails the whole `batchUpdate`, so `_apply_doc_content` retries with that request stripped (its index parsed from Google's error); see `docs/design/image-conversion.md`. [History](docs/design/module-history.md#toolsdocscontentpy).
  - `docs/editing.py` — text-range editing tools (`insert_doc_text`, `delete_doc_range`, `insert_page_break`, `insert_softbreak_paragraph`). `insert_softbreak_paragraph` joins lines with `"\v"` in a single `insertText` (the API keeps it one paragraph, like Shift+Enter) and sets `namedStyleType` explicitly over the inserted span. [History](docs/design/module-history.md#toolsdocseditingpy).
  - `docs/images.py` — tools (`insert_inline_image`, `insert_local_images`) plus the size validation, downscaling, and error rewriting shared by every `insertInlineImage` call site. The Docs backend fetches an image anonymously, so a `drive_file_id` must be shared `anyone`/`reader` first. Google's limits are 25 megapixels, 50MB, PNG/JPEG/GIF, and its own error names neither. `check_image_file` checks both limits before any upload, share, or embed call, reading only `stat()` and the header (it builds Pillow's format plugin directly, since `Image.open`'s decompression-bomb guard would skip huge headers); `check_drive_image_metadata` does the same for Drive sources from metadata. `auto_downscale` (default `False`) is opt-in: `downscale_drive_file` makes a `" (resized)"` copy and never mutates the original, and `prepare_local_image` uploads resized bytes for a local path. `downscale_image_bytes` runs via `asyncio.to_thread`, declines animated GIFs (returns `None`), and iterates when bytes, not pixels, are over. A bare `http(s)://` source is deliberately never fetched to pre-check; it gets `rewrite_too_large_error`, which names both limits because it can't tell which one was hit. `ImageShareLifecycle` is the one temporary-share lifecycle for an image-embedding doc edit, used by `_apply_doc_content` and `insert_local_images` (#908); route any new one through it rather than hand-rolling the steps (`docs/design/image-share-lifecycle.md`). `resolve()` runs the uploads/shares as a shielded gather and marks dirty every folder a result names in `created_in` (a resized `drive:` copy lands next to its original, not in the target folder; #666). `async with edit():` checkpoints before the first edit request (#904), marks the doc dirty on every exit and again when an abandoned request lands (#907), then revokes, shielded, and checkpoints again so a cancellation held off by the revoke's shield is still raised and logged. So a cancellation can surface after the edit fully landed: `edit_completed` tells a caller which, and `_replace_doc_content` passes its own lifecycle (`_apply_doc_content(lifecycle=...)`) so that case discards its backup copy instead of keeping it. [History](docs/design/module-history.md#toolsdocsimagespy).
  - `docs/anchors.py` — `resolve_heading_anchor`, the slug matching behind the anchor pass. It tries GitHub's non-collapsing hyphen scheme (hand-rolled) and GitLab's collapsing one (python-markdown's `toc` `slugify`), with `-1`/`-2` duplicate-heading suffixes, against the doc's full heading list. The fuzzy fallback (`_fuzzy_match`) tries the anchor's literal tokens at occurrence 0 first, and only then treats a trailing `-<digits>` as an occurrence index. A requested occurrence that doesn't exist returns `None`, never the nearest candidate. [History](docs/design/module-history.md#toolsdocsanchorspy).
  - `docs/tables.py` — tools (`insert_doc_table`, `insert_table_row`, `delete_table_row`, `insert_table_column`, `delete_table_column`, `merge_table_cells`)
  - `docs/style.py` — helpers (`_NAMED_STYLE_TYPES`, `_read_body_styles`, `_read_named_styles`, `_build_named_style_requests`, `_text_style_and_fields`, `_add_or_clear_field`) and tools (`style_doc_range`, `style_doc_table_cells`, `create_paragraph_bullets`, `delete_paragraph_bullets`, `get_doc_theme`, `get_doc_named_styles`, `apply_theme`). [History](docs/design/module-history.md#toolsdocsstylepy). Invariants:
    - `createParagraphBullets` has no `nestingLevel` field. The API infers each paragraph's level from its leading tabs *relative to the other paragraphs in the same call*, then consumes the tabs, and it is a no-op on a paragraph already in a list. So `create_paragraph_bullets` always `deleteParagraphBullets` first, expands each target to its contiguous same-`listId` neighbors (keeping their levels), and issues one `createParagraphBullets` per contiguous same-preset run.
    - `deleteParagraphBullets` leaves a level-N item indented 36pt × N, and `createParagraphBullets` reads that indent as depth on top of the tabs. So each run zeroes `indentStart`/`indentFirstLine` between its delete and its tab inserts; without it, re-bulleting a listed paragraph compounds its level (#1069).
    - A run's preset comes from the doc's own `lists` map (`glyphType` = numbered, `glyphSymbol` = bulleted) unless the caller passed `bullet_preset`; explicit always wins. Conflicting explicit presets joined by a shared context paragraph return `{"error": ...}` instead of picking one.
    - A run with no level-0 paragraph is wrapped with a throwaway 0-tab anchor paragraph (insert `"\n"`, create over the range +1, delete the anchor), the same fix as `emitter.py`; otherwise the whole run collapses to level 0.
    - To clear a nested field such as a link, omit the key from `textStyle` but name it in `fields` (`_add_or_clear_field`); the API rejects `link: {}`. Guard the request on `if fields:`, not `if text_style:`, since a clear-only call has an empty style.
  - `docs/layout.py` — tools (`create_header`, `create_footer`)
  - `docs/comments.py` — tools (`list_doc_comments`, `add_doc_comment`, `resolve_doc_comment`) via the Drive `comments`/`replies` resource, not the Docs API
  - `docs/named_ranges.py` — helper (`_create_named_range`) and tools (`create_named_range`, `create_bookmark`), extracted out of `content.py` (#371) since they're fully self-contained. The Docs API has no bookmark-creation endpoint — `create_bookmark` is a thin wrapper over `createNamedRange` spanning a single character; neither tool's output is a link target (only UI-created bookmarks/headings are).
  - `docs/doc_to_ast.py` / `docs/ast_to_markdown.py` / `docs/markdown_export.py` — the read side (`get_doc_as_markdown`, opt-in `include_comments` for non-resolved comments via the Drive `comments` resource). It walks `documents().get()` into the same AST the write side uses and serializes that to Markdown, instead of cleaning up Google's styled HTML export (`docs/design/doc-to-markdown.md`). A paragraph is a fenced code block only when *every* run is code-styled (Courier New), so a paragraph holding only one inline code span renders as a block (documented in `docs/known-limitations.md`). Exception (#951): a fence can't hold a link, so a code paragraph with a linked run renders as linked inline code spans instead. A linked run that is only line breaks doesn't count, and neither does a linked image. Every image renders through `_render_image`, which keeps its link, and one inside a code paragraph renders outside the fence (`_render_code_block`). Links come from `_link_url`, shared by text runs and images, which rebuilds a heading or bookmark link (reported by ID, with no `url`) as a same-document URL. Empty-runs paragraphs in table cells are kept as spacers, and `_render_cell` converts `"\n"` to `<br>` *before* stripping. Emphasis markers go inside surrounding whitespace (CommonMark flanking). `_text_run_to_run` turns every `"\v"` (soft break) into `"\n"`, and a plain run's `"\n"` renders as `<br>` with edge breaks outside its link (#1057); `get_doc_structure`/`find_in_doc` still decode only Courier New runs (`decode_code_run_text`). A nested table renders a placeholder note. [History](docs/design/module-history.md#toolsdocsdoc_to_astpy--docsast_to_markdownpy--docsmarkdown_exportpy).
  - `docs/ast.py` — dataclass schema
  - `docs/html_parser.py` — HTML→AST. [History](docs/design/module-history.md#toolsdocshtml_parserpy). Invariants:
    - Bare top-level text gets an implicit paragraph. `_tag_depth` counts open non-block tags, excluding `_VOID_TAGS` (stdlib `HTMLParser` never closes a void tag written without a slash), so text inside only an inline tag stays a no-op. `_finalize()` flushes the block still open at end of input.
    - `_emit_block_node(preserve_if_empty)`: a block's own first close keeps an empty node (`runs=[]`) as a paragraph boundary; a resumed frame's re-close (`_block_resumed`) still drops an empty result. A fresh `<p>` (only `<p>`, not `<li>` or headings, and not resumed) keeps whitespace-only runs, since `&nbsp;` lines are deliberate spacers. A bare `<hr>` appends an empty `Paragraph`. `<pre>` builds its node directly and applies the same fresh-vs-resumed rule itself, keeping a fresh `<pre>`'s whitespace.
    - Any `</ol>` or `</ul>` pops `_list_ordered` by count, whatever type opened it, and must run *before* `_resume_interrupted_block`. List frames match by `list_depth`, not tag: the frame is popped once its depth is reached, but the outer block is resumed only on an exact tag match.
    - `_resume_interrupted_block` flushes whatever block is open, unconditionally, before anything else.
    - Every leaf-node construction (`Heading`, `Paragraph`, `BulletItem`, `NamedBlock`) must pass `**self._blockquote_fields()`, which sets `blockquote_depth` and `blockquote_path` from the open-`<blockquote>` id stack (`docs/design/blockquote-representation.md`). Without the path, two adjacent quotes are indistinguishable (#1098). A top-level `Table` gets `blockquote_depth` only, at `</table>`, for its indent (#1097). `_make_bullet_item` clamps depth to `>= 0` for an orphan `<li>`.
    - Known gap: a resumed block's genuine trailing `&nbsp;` is dropped (#444).
  - `docs/emitter.py` — AST→Docs API requests, plus the multi-phase table fill (nested tables, cell styling). [History](docs/design/module-history.md#toolsdocsemitterpy). Invariants:
    - Bullet depth is encoded as leading `"\t"` on each paragraph's text, and `createParagraphBullets` computes levels only within one call. So each maximal contiguous run of same-`ordered` `BulletItem`s gets exactly one call; one call per paragraph creates separate lists and breaks numbering.
    - A run with no depth-0 item is wrapped with a throwaway 0-tab anchor paragraph (insert, create over range +1, delete), so every item's `nestingLevel` equals its depth, unclamped. A fragment whose parents were dropped rendering deeper than expected is intended (#714). Each `bullet_run_requests` entry is therefore a list of requests.
    - Tab consumption shifts later positions, so the bullet pass runs after all other per-node requests and before the `insertTable` pass, latest-position-first. Each `_PendingTable` position is decremented by the cumulative tab count of the runs before it (`utf16_len`, not `len`).
    - `insertTable` gives the table its indent, which no API field can reset afterward, and every empty cell its text style, from the paragraph at the insertion point. So each table gets a placeholder paragraph in the phase-1 text, reset to plain after the bullet pass by `_table_placeholder_requests` (a table between two same-preset list items sits inside their one bullet range; a quoted table keeps its quote's indent via `Table.blockquote_depth`, which `_quoted` still ignores). The table is inserted there, and the placeholder, pushed past the table, is deleted by the `deleteContentRange` right after the `insertTable` (`_inserted_table_length`). Never insert a table at the start of the next block's text: it takes that block's indent and first-character style (#1097). `_positional_insert_tail_start` keeps that delete in the positional tail by its place after an `insertTable`.
    - `_strip_bullet_leading_tabs` removes a literal leading tab from a bullet's own text (it would read as depth) and returns new `Run`/`Image` objects; it must never mutate caller-owned AST nodes. Dropping an authored leading tab is a deliberate, documented loss.
    - Blockquote nodes get a gray `borderLeft` and `indentStart` = `indentFirstLine` = 36pt × depth (`indentFirstLine` is absolute, not relative to `indentStart`). `createParagraphBullets` overwrites both indents, so a quoted `BulletItem`'s request runs after the whole bullet pass and before the table/image inserts, at the list level's own indents (`list_level_indents`, level capped at 8 as Docs caps `nestingLevel`) plus the quote's. Every position used after the bullet pass maps through `_after_bullet_pass`. `doc_to_ast.py` subtracts the level's indent when inferring depth.
    - A code-styled paragraph's internal `"\n"` breaks become `"\v"` (`_is_code_paragraph`) so a fenced block stays one Docs paragraph; `doc_to_ast.py` reverses it.
    - Table-cell images (#1073) go in during `fill_tables`, not phase 1, from the URIs in `CellImages`. `_run_group_fill_requests` writes a cell's text and styles as if no image were there, then each image (through `CellImages.insert_requests`) at the offset of the text before it, latest first. Whenever there are cell images to embed, every cell-fill `batchUpdate` goes through `CellImages.execute`, which drops an unfetchable image and resends. It splits a batch only at a failed image, never elsewhere: an earlier cell's text moves every later position. Its request bookkeeping holds the request dicts and is cleared after each batch, so an `id()` key can't outlive its request. `_text_offset_since_last_table` counts an image only while it's still in `CellImages.uris`, so a dropped one doesn't shift the nested table after it. `_apply_doc_content` gives a resolved cell image missing from `CellImages.embedded` an `error` (`docs/design/image-conversion.md`).
    - Docs joins the left borders of adjacent paragraphs with the same border and indents into one bar, whatever their spacing. So `_with_quote_separators` puts an unbordered empty paragraph, collapsed by `_collapse_paragraph_requests`, between two adjacent quoted nodes whose `blockquote_path`s aren't one a prefix of the other (#1098). `_block_spacing` gives a code block 8pt above and below, and a quote 8pt where it meets content outside it. A separator is spaced on one side only (below the quote before it), and a `Heading` or TITLE/SUBTITLE `NamedBlock` gets no quote-edge space, since an explicit value replaces its named style's own. `_spacing_requests` puts `spaceAbove` on a node's first Docs paragraph and `spaceBelow` on its last, since a node with a `"\n"` in its text spans several. A quoted `BulletItem`'s spacing is emitted after the bullet pass, like its quote styling. `_build_blank_para_before_table_collapses` resets every empty paragraph before a table to plain, a backstop since the table placeholder (above). It deletes the bullet first, because `deleteParagraphBullets` adds indent, then clears indents and border. It leaves the paragraph between two tables at full height, so they don't touch.
- `tools/cache.py` — `refresh_cache`, `set_cache_ttl`/`get_cache_ttl` (runtime TTL change, no restart needed)
- `cache.py` — the five SQLite caches (GHSA-8jqx-w7j8-6xwm). Invariants:
  - Every read and store filters on the instance's fixed `principal` (the Google identity, bound by `auth.ensure_cache_principal` from `reauth.before_call` and `_build_context`); unbound, reads miss and stores do nothing. Invalidation (`mark_dirty`, `_mark_dirty_prefix`, `mark_all_dirty`) deliberately doesn't filter, so a change reaches every identity's copy; only TTL expiry marks just the own row. Rebinding replaces all five instances (`auth._bind_caches`), never mutates one, so an in-flight fetch stores under the identity it fetched as. The replacement shares the old instance's `_Invalidations`, so #698's epoch guard spans the rebind; keep invalidation state on that object, never on the instance. A new read or write goes through `_fetch_row`/`_replace`/`_store_if_fresh`.
  - A cache's connection opens at first use (the `_conn` property), not at construction. A context's default (unbound) instances are replaced by bound ones once the identity resolves, so they open the DB only if it never does (their `mark_dirty` still writes). A replaced instance is left for its in-flight fetch and closes its connection in `__del__`. No `chmod(follow_symlinks=False)`: it raises `NotImplementedError` on glibc < 2.32; check with `lstat`, then a plain `chmod` (`_chmod_own_file`).
  - `fetch_sheets` serves a stale entry only on a transient error (`_is_transient`: 5xx, 429, transport). A 403/404 is Google's answer and must propagate; a `RefreshError` must reach #873's path.
  - The default DB is in the user's own cache directory (`default_db_path`, pure at import); `_prepare` creates it `0700` and the files `0600`, and refuses another user's or a symlinked one (`_CacheFileRefused`, which `_open` answers with `:memory:`, never by deleting). A schema change bumps `_SCHEMA_VERSION`, which drops and recreates the table.
- `tools/calendar.py` — Calendar API tools
- `local_files.py` — the local-file access policy, `LOCAL_FILE_ACCESS=full|roots|off` (#796, `docs/design/local-file-access-policy.md`). Resolved once at import from env and argv (`cli_transport`, shared with `main()`): the default is `full` under stdio and `off` otherwise, and `_timed`'s `request_over_http` tripwire refuses a defaulted `full` that reaches an HTTP request. Invariants:
  - Every local read or write a tool makes goes through `check_read`/`check_write`, *before* any `stat` of the path, so a refusal reads the same whether or not the path exists. The check returns the resolved path. Where a site uses it (`_upload_local_file`'s upload, `_read_doc_source_file`, `import_csv_to_sheet`, Gmail attachments) it narrows the window before the I/O; writes keep the caller's path, since `_write_atomically` resolves a symlinked destination itself. Neither closes the check-then-use race, which is a documented known limitation. Take a filename or suffix from the caller's own spelling, so a symlink keeps its link name. A malformed path (a NUL byte) is a `LocalFileAccessError` too, so a per-item site fails only that item.
  - A folder walk checks each entry, not just the root: a symlink inside a root can point anywhere. In `sync_folder` a refusal is a `local_read_fail` plan step (`_sync_policy_refusal`). `_sync_local_check` picks the check from what the plan can do to the local side (read, write, or either for a both-sides bidirectional entry) and returns None for a name on one side only that the direction never touches, which is skipped unchecked. Wrap a walk in `local_files.many_checks()`, which stats the deny-list once for the whole walk instead of once per entry, on the loop. It also resolves each parent directory once, keyed by the path's raw spelling. Never normalize it lexically (`abspath`/`normpath`): `link/..` is the parent of the link's target, and collapsing it first let a write land in a deny-listed directory (PR #1039 QA round 2). A relative path bypasses the cache.
  - `resolve_policy` never raises: an invalid setting resolves to `off` with `Policy.error` set, and only `main()`'s serving path exits on it (`exit_if_invalid`), so `mcp-gee-sweet auth` and `gen_tool_docs.py` still run.
  - A tool that can only work on local files takes `@tool(local_only=True)`, which `off` mode doesn't register. A tool with an optional `local_path` checks it at entry, before any fetch; `write_capped_result_to_disk` is the backstop and also checks the joined `default_filename`.
  - A new tool parameter that takes a local path fails `tests/test_server.py::TestLocalPathToolsAreCovered` until the tool is added to `_LOCAL_ONLY_TOOLS` or `_OPTIONAL_LOCAL_PATH_TOOLS` there, with its check in place.
- `tools/response_limits.py` — shared response-size safety net (`enforce_response_size_cap`, `write_capped_result_to_disk`); imported cross-package the same way `tools/drive/__init__.py`'s `_quota_error_text` is. Cap configured via `MAX_TOOL_RESPONSE_CHARS` (see `docs/configuration.md` for the current default — raised in issue #519 after live-testing found the client-connection-death failure mode it defends against no longer reproduces at the old default's scale, kept as defense-in-depth for other/untested MCP clients); see `docs/decisions/decision-response-size-cap-generalization.md` and `docs/decisions/decision-response-size-cap-reevaluation-519.md`

`__init__.py` loads `src/mcp_gee_sweet/.env` via `python-dotenv` before importing `server`, so env vars from that file are in `os.environ` by the time any module-level `os.environ.get()` runs. Priority: real env var > `.env` > default.

**Startup / auth** (`spreadsheet_lifespan`): MCPServer lifespan context manager that authenticates on server start and injects a `SpreadsheetContext` (holding `sheets_service`, `drive_service`, `docs_service`, `calendar_service`, and `activity_service`) into every tool call via `ctx.request_context.lifespan_context`. It also stamps the same `SpreadsheetContext` into a module-level `auth._lifespan_context`, readable via `auth.get_lifespan_context()` — this is what `server.py`'s static `server://auth-status` resource reads instead of going through Context (see the MCP resources note below).

**The lifespan runs once per connection under SSE, not once per process.** mcp v2's `Server.run` enters `spreadsheet_lifespan` for every SSE connection; stdio has exactly one. So per-connection auth outcomes belong on the `SpreadsheetContext` it yields, never in a module global that a later connection's lifespan can overwrite or reset. PR #828 (#811) round 1 kept its degraded-start message in a global, and QA caught a second connection clearing the message the first still relied on. Genuinely process-wide decisions (e.g. "don't retry the consent flow", the shared `_consent_attempt`) are the exception, and should say so in a comment.

**No usable OAuth token (#811):** under stdio the lifespan never starts a consent (stdout is the JSON-RPC channel). `AUTH_METHOD=oauth`, or the waterfall with no service account/ADC fallback, starts *degraded*: the yielded context has every service `None` and `unauthorized_message` set, and on that connection each tool call first offers re-authorization instead of running (#873, below); `server.py`'s `_timed` wrapper raises the degraded message itself only when no offer can be made. It raises rather than returns, because a `{"error": ...}` dict would fail a list-typed tool's output schema. Under SSE the consent runs with its prompt on stderr and an `OAUTH_CONSENT_TIMEOUT_SECONDS` bound, and any failure degrades that connection. The recovery paths are the tool call's consent offer (#873) and the `mcp-gee-sweet auth` subcommand (`auth.run_auth_command`, argv parsing in `server._auth_main`). `scripts/oauth_setup.py` is only a QA wrapper over the same `run_consent_flow`/`write_token_json` (0600) helpers.

**The SSE auth phase runs off the event loop (#833).** Design and the races behind each rule: `docs/design/sse-consent-off-event-loop.md`. Invariants:
- Nothing in the lifespan's auth phase runs on the loop. `_oauth_creds_async` runs the token load/refresh and the consent on daemon threads (`_run_in_daemon_thread`), never `asyncio.to_thread`: interpreter shutdown joins executor threads, which would move the hang to exit. Every wait goes through `_await_unless_shutdown`, which polls sse_starlette's `AppStatus.should_exit`, the only shutdown signal a lifespan can see. Without it, uvicorn waits on the connection and SIGTERM hangs until the wait ends.
- One consent attempt at a time, process-wide on purpose: `_consent_attempt` is shared, and connections arriving during it await the same future. A failed *lifespan* attempt turns consent off in `_ConsentAttempt._on_settle`, on the loop, before any waiter sees the failure, and the lifespan never retries consent in the process (each new connection would wait out the timeout again). A tool call's user-started consent is exempt from both (see #873 below).
- A token load runs on its own thread, so it can race an attempt that settles meanwhile. On the loop, re-check `_interactive_consent` before starting an attempt, and reload the token if `_consent_successes` changed during the load. Don't reuse a finished attempt's credentials: a load that starts after a success and still finds no usable token needs a new consent.
- Outside stdio the lifespan never raises: `spreadsheet_lifespan` turns any auth failure into a degraded connection. A lifespan that raises after an `await` leaves a POST that raced in parked forever in mcp's SSE transport, and SIGTERM hangs on it (python-sdk#3616). Only stdio (`set_raise_auth_failures(True)` in `server.main()`) keeps #790's fail-fast exit.

**A tool call re-authorizes OAuth in place (#873).** Design: `docs/design/oauth-reauthorize-from-tool-call.md`. Invariants:
- A non-retryable `RefreshError` is detected at `thread_http`'s transport (`_RefreshTrackingHttp`), not in tool code: most tools catch it and return `{"error": ...}` (#906). `_timed` runs every call inside `track_refresh_failures()` and replaces the result with `reauth.after_refresh_failure`'s offer. Any new request path must go through `thread_http`.
- The offer is `UrlElicitationRequiredError` when the client declares `elicitation.url`, else `reauth.ReauthorizationRequired` (a `ToolError`) carrying the URL. A tool call never opens a browser.
- A tool call's consent shares the process-wide `_consent_attempt` with the lifespan's, but is `user_started`: it ignores `_interactive_consent` (so it works under stdio), no departing waiter stops it, and its failure doesn't turn consent off. A tool call may join a lifespan's attempt (marking it `offered`, so it isn't stopped), but a lifespan never waits on a tool call's: it degrades at once with `OAuthConsentRequiredError(disables_consent=False)` (PR #925 QA round 1). A nearly expired tool-call attempt is replaced, not stopped: it keeps listening to its own deadline (`join_group_of`), because a client holds its link, and whichever of the two completes notifies both attempts' clients (PR #925 QA round 2).
- New credentials go through `publish_oauth_credentials`, which alone sets the Gmail gate for them; a reload runs `_oauth_creds(record_gmail=False)`. Each context adopts a newer generation in place (`adopt_published_credentials`) on its next call. A mid-session failure that adopts a token asks for a retry instead of re-running the tool, and the offer carries the tool's own result (`describe_outcome`).

**CodeQL flags logging any value whose name looks like a secret.** `py/clear-text-logging-sensitive-data` is a *high* alert that blocks merge. It keys on names, so logging a raw `OAUTH_CONSENT_TIMEOUT_SECONDS` value (an integer) tripped it on PR #828 after QA had already passed. Don't interpolate the value of an `OAUTH_*`/`*TOKEN*`/`*SECRET*`/`*PASSWORD*`-named env var or variable into a log message; name the setting without echoing it.

The project philosophy is to be as powerful and flexible as possible by default, while giving security-conscious users the configuration knobs to lock things down. Two mechanisms reflect this:

- **Auth** (`AUTH_METHOD`): out of the box the waterfall tries everything so the server just works; setting `AUTH_METHOD` restricts it to exactly one method with no fallback.
- **Tool surface** (`ENABLED_TOOLS` / `--include-tools`): by default all tools are registered; setting `ENABLED_TOOLS` to a comma-separated list of function names limits the server to exactly that subset. This lets operators expose only the tools their users need.

By default (`AUTH_METHOD` unset), auth falls through in order: OAuth (`CREDENTIALS_PATH`/`TOKEN_PATH`) → service account (`CREDENTIALS_CONFIG` or `SERVICE_ACCOUNT_PATH`) → Application Default Credentials. OAuth is tried first because it authenticates as the user (full personal Drive access); service account is a fallback for headless/server deployments.

Set `AUTH_METHOD` to pin a specific method with no fallback — removes ambiguity for security audits, CI, or testing a tool's behavior under a known credential type:
- `AUTH_METHOD=oauth` — OAuth only; fails fast if the OAuth client JSON is missing, and starts degraded (see above) if there is no usable token
- `AUTH_METHOD=service_account` — service account only; requires `CREDENTIALS_CONFIG` or `SERVICE_ACCOUNT_PATH`
- `AUTH_METHOD=adc` — ADC only

**Logging** (`DEBUG_LEVEL` env var): when set, configures the `mcp_gee_sweet` package logger and `uvicorn.access` logger to the given level (`DEBUG`, `INFO`, `WARNING`, `ERROR`). The `_timed` wrapper in `server.py` emits one `INFO` line per tool call to `mcp_gee_sweet.access` — format: `"IP" "UA" "TOOL name" status elapsed`. IP/UA come from `ctx.request_context` in SSE mode; fall back to `-` in stdio. `LOG_FILE` and `ACCESS_LOG_FILE` env vars write logs to file (required for stdio where stderr is dropped by the host). Runtime config lives in `src/mcp_gee_sweet/.env` (gitignored); template at `src/mcp_gee_sweet/.env.template`.

**Tool registration** (`tool` decorator wrapper): A custom `@tool()` decorator wraps `@mcp.tool()`. It checks `ENABLED_TOOLS` (set via `ENABLED_TOOLS` env var or `--include-tools` CLI arg) and skips registration for any tool not in the allowlist. This is how tool filtering works — tools simply aren't registered with MCPServer rather than being conditionally hidden.

**Async execution** (`execute_in_thread` + `thread_http`, in `http_transport.py`; full rationale in `docs/decisions/decision-async-tool-execution.md`, [History](docs/design/module-history.md#async-execution)):
- Every `@tool()` function must be `async def`, even one with no API calls: `_timed` awaits it, so a plain `def` raises `TypeError` (`test_server.py::TestAllToolsAreAsync` guards this).
- Wrap every `.execute()` as `await execute_in_thread(chain.execute, service)`. Never write `asyncio.to_thread(chain.execute, http=thread_http(service))`: the kwarg is evaluated on the event-loop thread, so concurrent calls share one non-thread-safe `httplib2` transport.
- A per-thread transport's pooled connection goes stale while the server idles (#1052). `thread_http` builds `_RefreshTrackingHttp` over `_StaleConnectionHttp`, whose `_conn_request` override tracks staleness per connection, because a busy transport can still hold an idle token-endpoint connection. It closes a connection idle longer than `_IDLE_RECONNECT_SECONDS` before reuse, by wall-clock time, since `time.monotonic()` stops during system sleep. It also closes one that fails with a `_CONNECTION_ERRORS` error, since httplib2 itself drops a connection only on a socket timeout. `_RefreshTrackingHttp` resends a read once (GET, HEAD, or a POST carrying `x-http-method-override: GET`, which googleapiclient sends for a URI over 2048 characters), and `_ResendingRefreshRequest` resends a token refresh once. Never resend a write: the server may have applied it before the connection died.
- `thread_http` must keep what googleapiclient's `build_http()` gives a `build()`-built client (`docs/decisions/decision-http-socket-timeout.md`), and a bare `httplib2.Http()` has neither setting: a per-socket-operation timeout (`HTTP_TIMEOUT_SECONDS`, default googleapiclient's 60 s, capped at one day), and 308 removed from `redirect_codes` (`_StaleConnectionHttp.__init__`), since Drive uses 308 for resumable uploads. `tests/test_http_transport.py::TestMatchesBuildHttp` compares the two. A timeout re-raises as a `TimeoutError` whose message says whether the connection layer resent a read or a write may have landed.
- Six multi-call tools (`sync_folder`, `get_multiple_sheet_data`, `get_multiple_spreadsheet_summary`, `import_csv_to_sheet`, `share_spreadsheet`, `share_file`) fan out with `asyncio.gather(..., return_exceptions=True)`.
- A `ctx.report_progress()` call inside a gathered per-item coroutine must be wrapped in its own try/except, or a dropped client session turns an already-successful item into a failure.
- Cleanup that must run when a tool call is cancelled (revoking a temporary share, deleting a temp file) needs `with anyio.CancelScope(shield=True):`, not just a `finally`. mcp cancels a request through an anyio cancel scope, which re-delivers the cancellation at every `await`, including the cleanup's own `await` inside `finally`. Shield the step that creates the resource too, or one created mid-`gather` is never recorded for cleanup. Keep shielded work bounded: a cancel waits for it. `images.ImageShareLifecycle` is the reference (PR #877, #908).
- A cancelled `execute_in_thread` call still runs to completion: `asyncio.to_thread` can't stop a thread that has started. Before an unshielded write that a shielded step preceded, `await anyio.lowlevel.checkpoint()` so a held-off cancellation lands before the request is sent (#904). Cache invalidation for a write that can be cancelled mid-flight goes inside `with after_abandoned_calls(callback):` (`http_transport.py`), which reruns the callback on the loop once an abandoned request's thread finishes (#907); marking dirty only on the cancel path leaves a window where a concurrent read re-caches the pre-edit state.
- `cache.py`'s SQLite I/O stays synchronous on purpose (see `cache.py::_open()`). `_BaseCache.snapshot_epoch()`/`store(..., epoch=...)` stop a mid-fetch `refresh_cache()` from being overwritten, per key (`SheetStructureCache`, `SheetDataCache`, `DriveFolderCache`). Size-bounded caches share `_get_sized`/`_store_sized`.
- To unit-test real cross-thread concurrency, put the barrier inside the mocked `.execute()`, not `.list()`/`.create()`, which run on the event-loop thread (see `tests/drive/test_transfer.py::TestSyncFolderRecursive::test_recursive_sibling_subfolders_descend_concurrently`).

**Two Google API clients**: The server builds both a Sheets client (`sheets/v4`) and a Drive client (`drive/v3`). Most tools use only the Sheets client; `list_spreadsheets`, `create_spreadsheet`, `share_spreadsheet`, and `list_folders` use Drive. `create_spreadsheet` uses Drive to create the file (so it can place it in a folder), not the Sheets API.

**A1 notation helpers**: `_parse_a1_notation`, `_column_index_to_letter`, and `_letter_to_column_index` convert between A1 ranges and the 0-based row/column indices the Sheets batchUpdate API requires. The Sheets values API uses A1 notation directly; batchUpdate requires numeric indices — keep that distinction in mind when adding new tools.

**Docs API indices are UTF-16 code units, not Python code points**: every `startIndex`/`endIndex` in the Docs API counts UTF-16 code units — an astral-plane character (most emoji, some CJK/math symbols) is one Python `str` character but a 2-unit surrogate pair. `content.py`'s `find_in_doc` and `indices.py`'s `_collect_doc_paragraphs` account for this via `utf16_len`. `emitter.py`'s offset math (table positions, paragraph-style ranges, inline run-style ranges) does not — it derives offsets from plain `len()`/`enumerate()`, a confirmed-pattern bug tracked in #358. Any new code deriving a Docs API index from Python string length needs `utf16_len`-style accounting instead of raw `len()`.

**Sheets API `TextFormatRun.startIndex` is also UTF-16 code units.** `update_cells` (`tools/sheets/data.py`) accepts a rich-text cell as a list of `{"text", "hyperlink"}` runs; `_build_rich_text_cell` computes offsets with `_utf16_len` (`sheets/helpers.py`, delegating to `docs/indices.py`). A `data` array with only plain cells uses one `values().update()`. A mixed array writes plain cells by position via `values().batchUpdate()` and rich-text cells via a separate `batchUpdate`, so the two passes never touch each other's cells, and returns `{"values_update", "rich_text_update"}`. Never blank rich-text positions in the values write and rely on the second call to fill them: if it fails, the data is lost. [History](docs/design/module-history.md#sheets-api-textformatrunstartindex-is-also-utf-16-code-units).

**MCP resources**: `server://auth-status` (active auth method and Drive capability limits) and `spreadsheet://{spreadsheet_id}/info` (sheet list and grid properties). mcp v2 has no `get_context()` and can't inject Context into a *static* resource. So the template resource `get_spreadsheet_info` takes `ctx: Context` like a tool, while the static `get_auth_status` reads the process-wide `auth.get_lifespan_context()` singleton. See `docs/decisions/decision-mcp-v2-resource-context-access.md`. [History](docs/design/module-history.md#mcp-resources).

**`batch_update` tool**: This is a passthrough to the Sheets `spreadsheets().batchUpdate()` endpoint and accepts raw request objects. It's the escape hatch for any operation not covered by the named tools (formatting, conditional formatting, dimension properties, etc.).

## Development workflow

**MCP restart**: after `docker compose restart mcp-gee-sweet`, restart Claude Code too; it doesn't reconnect to the SSE server. A team role's stdio `mcp-gee-sweet-<name>` server imports the package once at session start, so a live tool call after a mid-session edit runs the *pre-edit* code, which can look exactly like a real bug. To live-verify a same-session change, use a fresh interpreter: `uv run python3 -c "..."` with `mcp_gee_sweet.auth._oauth_creds()` plus `googleapiclient.discovery.build(...)`. That's also the only way to inspect raw fields no tool surfaces (e.g. `paragraph.bullet`, `lists`). The fresh interpreter is only for code this branch changed. To reproduce a bug in code the branch doesn't touch, or to gather evidence for a ticket about one, call the affected tool itself on an `mcp-gee-sweet-*` server this session may call: that's the path a user hits, and a script that rebuilds the tool's requests can differ from it. [History](docs/design/module-history.md#mcp-restart).

**Generated tool docs**: `docs/tools.md` and the "Tool filtering" section of `docs/configuration.md` are generated by `scripts/gen_tool_docs.py` from the tool source (names, signatures, docstrings) — do not hand-edit the tool tables in either file. The script is wired into `.pre-commit-config.yaml` and runs whenever a file under `src/mcp_gee_sweet/tools/` or either generated doc changes; it fails the commit if a tool has no docstring, if a tool doesn't match any section in the script's `SECTIONS` config, or if a `SUBSETS` entry references a renamed/removed tool name. Run it manually with `uv run python scripts/gen_tool_docs.py`.

**PR creation**: open PRs ready-for-review (`gh pr create`, no `--draft`), not as drafts — draft should be an explicit, stated exception (e.g. genuinely incomplete work you want visible early), not the default. `gh pr merge --admin` refuses a draft PR outright (`merge-pr.md` now handles it by readying first), so an unnecessary draft is pure friction at merge time with no upside.

**Regression vs. pre-existing bug after a dependency bump**: don't answer from memory or changelogs. Install the old pinned version in a scratch venv and check the API surface directly, e.g. `python3 -m venv /tmp/x && /tmp/x/bin/pip install "mcp==1.27.1" && /tmp/x/bin/python -c "...hasattr(...)"`. [History](docs/design/module-history.md#regression-vs-pre-existing-bug-after-a-dependency-bump).

**Verify a ticket's API premise live before implementing, not after.** A field in a Google API discovery schema isn't necessarily writable; the schema lists read-only fields as ordinary properties. Before building on a capability not already confirmed live in this codebase, check the live discovery document with the scratch-script approach above: read the field's own `description` for a "read-only" note, and confirm some request type actually writes it. (`ParagraphStyle.tabStops` cost a full dev+QA cycle this way; #404.) [History](docs/design/module-history.md#verify-a-tickets-api-premise-live-before-implementing-not-after).

**Procedural feedback → the governing command file, not memory.** If the human's feedback corrects a repeatable team-workflow step that a `.claude/team-roles/*.md` or `.claude/commands/*.md` file governs (or should), edit that file, through Bob's prompt-QA gate (`.claude/team-roles/bob.md`); `.claude/commands/retro.md` treats this as a command decision. A memory-only fix is retrieved heuristically and loses to whatever the loaded prompt says. Memory is still right for project context, external pointers, and one-off judgment calls. [History](docs/design/module-history.md#procedural-feedback--the-governing-command-file-not-memory).
