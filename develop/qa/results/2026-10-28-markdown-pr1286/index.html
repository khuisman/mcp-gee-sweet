    Findings from this round's live checks¶

    • F1 (#1288): create_paragraph_bullets on "B" in 1. A / - a1 / 2. B / 3. C, with no preset or level change, leaves 1. A and moves B and C to a new list showing 1. B, 2. C. Its same-listId expansion stops at the nested bullet item, so it re-bullets only B and C.
    • F2 (#1241): 1. P / 1. a / 1) b / 2. Q renders b as b.; 1. x / 1) y renders y as 2. The AST has no list boundary, so the marker change is lost. The rendering didn't change with this PR.
    • F3: raw API. createParagraphBullets over a range whose paragraphs are all already listed changes nothing (listId kept, either preset). Over a range that mixes unlisted paragraphs with a listed one, the unlisted ones join the listed paragraph's existing list; the listed one isn't moved to a new list.
