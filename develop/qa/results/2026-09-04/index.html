    Failures¶

    TC-D18/D19/D20/D23/D24/D176 — share_spreadsheet broken on Shared Drives (one root cause, BUG-SS) Expected: share succeeds, entries land in successes. Observed: every call returns failures:[{"error":"Failed to share: File not found: <id>."}]. Reproduced on a throwaway sheet and the real fixture. Root cause (confirmed in source): share_spreadsheet._share_one's permissions().create() call omits supportsAllDrives=True — the only permission op in tools/drive/sharing.py missing it (update_permission, remove_permission, list_permissions, transfer_ownership, share_file all have it). Since fixtures + the default DRIVE_FOLDER_ID are now a Shared Drive (#305), the tool fails on any file it's pointed at in this deployment. share_file works (functional workaround exists). One-line fix.

    TC-D124 — stale test-case assumption, not a tool bug list_permissions on the Shared-Drive fixture shows organizer/fileOrganizer roles, no owner (owners: [], correct for Shared Drive items). The TC's "expect an owner entry" check predates the #305 migration. Test-case fix applied (see below).

    TC-D01 — create_spreadsheet response has no web link Response is {spreadsheetId, title, folder}; the TC expects a web link. Siblings (copy_file, create_folder, get_file_metadata) do return one. Judgment call, not filed as a bug yet — see Bugs found.

    TC-D13 — stale test-case assumption list_spreadsheets(default) no longer includes the fixture spreadsheet, because the default folder now resolves to the Shared Drive root (DRIVE_FOLDER_ID) and the fixture lives in the FOLDER_ID subfolder — correct post-#305 behavior, stale TC text.

    TC-D40 — list_files max_results cache-poisoning (BUG-CACHE) list_files(FOLDER_ID, max_results=2) returned 5 on the first call (a prior default-max_results call's cache hit ignored the smaller limit); a subsequent small-max_results fetch then stores the truncated list, so later default-size calls get only the truncated result until refresh_cache. Reproduced twice. Root cause: the folder-listing cache key omits max_results. Affects list_files, list_spreadsheets, list_folders (shared cache). Silent, persistent wrong data — the most severe finding this pass.

    TC-D167 — stale #519-cap test premise, same class as TC-DOC80 export_file's base64-xlsx response no longer trips the (raised) MAX_TOOL_RESPONSE_CHARS default at this fixture's size. Not a regression; needs the same low-cap re-run method as TC-DOC80 (#678) — tracked as a follow-up, not re-run this pass (lower priority: export_file's cap-check code path is exercised and passing via TC-DOC80's sibling get_doc_content check and unit tests).

    TC-W02 — test-prompt bug, not a tool bug Prompt used single-quote string delimiters in a Sheets formula (=A2&' '&A3); Google Sheets requires double quotes, producing #ERROR!. Re-run with =A2&" "&A3 succeeded; USER_ENTERED mode independently confirmed. Test-file fix applied (see below).

    Process notes¶

    • Playwright auth gap, corrected mid-pass. Every shard initially hit an unauthenticated Playwright browser (redirects to Google sign-in), concluded Playwright was unusable, and fell back to API-level-only verification. Once the user authenticated Playwright mid-pass, corrections were sent to live shards (one was misdirected due to an agent-ID mix-up on my end, caught and fixed) and a targeted re-verification pass redid the highest-value already-completed visual checks (10 docs/transfer TCs + 7 Sheets TCs) with real screenshots — all confirmed, no discrepancies. Filed PR #686 to make Playwright-auth verification a real pre-flight step (not just a connection check) for future passes.
    • Service-account calendar fixture gap. The SA wasn't subscribed to the real fixture calendar, so the Calendar shard ran its full suite against SA-owned substitute calendars (still valid tool-behavior coverage). A targeted OAuth re-run against the real fixture closed the gap for the 6 identity-sensitive cases plus 2 that only work under OAuth (attendee invites) — all PASS, real fixture left untouched.
    • Cross-shard fixture interference, resolved. The Sheets shard's writes to the fixture spreadsheet transiently corrupted the Drive-transfer shard's CSV-export comparison mid-pass. Re-checked after Sheets restored the fixture to seed state — clean, confirms it was timing, not a product bug.
    • OAuth token refresh issue (infra, not QA). A fresh script/process using the main-checkout token.json now hits invalid_grant on refresh; already-running server processes are unaffected (cached token). Recommend re-running scripts/oauth_setup.py before the next session needs a fresh OAuth connection. This blocked one live re-verification (TC-DOC159); disposed via a source-diff argument instead (code path unchanged since its last live PASS).
    • All-slots release-QA rule and the "verify Playwright first" fix were both codified as command-file PRs (#685, #686) during this pass, per direct user instruction, rather than left as one-off in-conversation guidance.
