    Bugs to file¶

    BUG-1: add_chart fails for any multi-column, multi-row data range¶

    Severity: High — affects all practical chart use cases. Error: "ChartSourceRange ranges require all rows or all columns to have length of 1" Root cause: charts.py passes the full range as a single source range object. The Sheets addChart API requires separate source range objects for each column — one for the domain (X axis / categories, typically column A) and one per series (subsequent columns). Fix direction: Parse the A1 range into per-column ranges. Split into domain range (first column) and series ranges (remaining columns), pass as separate entries in sources. Confirmed workaround: Single-column ranges work (TC-C03 with B1:B5 passed).

    BUG-2: add_chart HISTOGRAM type uses wrong API spec¶

    Severity: Medium — HISTOGRAM specifically broken even after BUG-1 is fixed. Error: "Invalid value at requests[0].add_chart.chart.spec.basic_chart.chart_type, HISTOGRAM" Root cause: HISTOGRAM is not a valid BasicChartType enum value. The Sheets API uses histogramChart (a separate spec field) rather than basicChart.chartType = HISTOGRAM. Fix direction: In charts.py, detect chart_type == "HISTOGRAM" and build a histogramChart spec instead of a basicChart spec.

    Environment findings¶

    Quota blocker: service account Drive storage quota exhausted¶

    Affected TCs: TC-D01–D12 (create), TC-D43, TC-D67–D69 (copy_file), TC-D88–D92 (upload_file), all download/sync tests. Cause: The write test suite added 1000+ rows and 5+ columns to the fixture spreadsheet (TC-W16, W17–W20), consuming the service account's Drive storage quota. This is not a bug in the tools — all affected tools return clear storageQuotaExceeded errors. The service account documentation should note this limit. Recommendation: Add a note to setup.md that service accounts have limited Drive storage quota. Destructive write tests should reset fixtures promptly to avoid accumulating quota usage.
