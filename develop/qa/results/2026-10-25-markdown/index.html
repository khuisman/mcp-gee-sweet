    Markdown rendering re-run for PR #1228 — 2026-10-25 (#1116, #1071)¶

    The re-run scope from docs/design/markdown-parser.md §"Re-run scope", through the four entry points that use _md_to_html (EP-1 to EP-4). EP-5 to EP-8 don't use it and were not run. QA round 3 of PR #1228.

    Result: 6 of 33 TC rows pass every EP-1–EP-4 cell in both runs (TC-MD101, TC-MD109, TC-MD111, TC-MD111F, TC-MD115, TC-MD204; TC-MD111/111F after LK-12's stale expectation was corrected, F5); the other 27 fail. Both runs complete. Run 2 rendered identically to Run 1 in every TC and entry point (132 Doc pairs, page by page): the only pixel differences were a text caret (2 px wide) or a spell-check squiggle (2 px tall), plus Run 1's squiggles under "fastqueue" in TC-MD302 EP-2/EP-4 pages 3 and 16. No nondeterminism (Rule 4).

    Setup¶

    • Code under test: PR #1228 head 7ad1576b, served by mcp-gee-sweet-kit (Lane B QA worktree reset to the PR head, server reconnected after the reset). LOCAL_FILE_ACCESS stdio default (full).
    • Folders: QA-MD-2026-10-25-run1 and -run2 under TEST_FOLDER_ID (264 Docs). Trashed after recording.
    • Playwright: account check passed (fixture doc title matched) before the first capture; the shared-browser mutex in run.md was held around each capture batch.
    • Method: as in the 2026-10-18 Phase 2 run. One browser_run_code_unsafe call per batch set a 1400×2200 viewport and captured each Doc page by page (.kix-appview-editor scrollTop step 1900) to docs/qa/screenshots/md/<run>/EP-<n>/<TC>-<k>.jpeg (gitignored). EP-1 was judged case by case; EP-2/3/4 were pixel-compared with EP-1 page by page, and Run 2 with Run 1 page by page, (grayscale, threshold 40, Docs chrome, outline pane and caret masked). Every sibling matched EP-1; the only differences were a text caret (≤62 px) and, in TC-MD302 EP-2/EP-4, spell-check squiggles under "fastqueue" (checked by eye: same content).
    • Inputs: EP-1/EP-2 sent the fixture text inline; EP-3/EP-4 read the file. EP-1 and EP-3 rendering pixel-identically confirms the inline copies matched the files (including md-lists-nesting.md's tabs and md-breaks-rules.md's trailing-space hard break). md-long-document.md was confirmed to be an exact concatenation of r01–r16 twice before typing it.
    • TC-MD111 also ran EP-1 to EP-4 with autolink_urls=False (row TC-MD111F).
    • TC-MD301 scope is DS-14 only (the other docstart/ files produced the same AST and aren't in the re-run scope).

    What this PR changed on screen (vs. the 2026-10-18 baseline)¶

    Fixed and passing now: D1 nesting at 2/3/4 spaces and tabs (TC-MD106 nesting correct in all 16 cases; TC-MD016's 2-space sub-bullets nest), 1) ordered lists (LM-03), #hashtag/seven-hash paragraphs (HD-02, HD-04), bold inside italic (EM-04, IN-05), strikethrough, \ escapes (ES-01), www./email autolinks (LK-06, LK-07), table after a paragraph (TB-08, D2), backslash hard break no longer shows \ (BR-03), two quotes split by a blank line (BQ-09, AB-067), whole inline matrix (TC-MD204 32/32).

    Still failing, all on open issues except the F-items below: soft line breaks become paragraph breaks everywhere (#1093, closed into bundle #1230 on 2026-10-25 — still open there); numbering restarts after a nested list of the other type (#1072); loose lists lose bullets (#1115/#1111, the "worse until #1164" items); blocks inside list items fall out to the margin (#1094); rules render as empty paragraphs (#1096); column alignment ignored (#1095); ordered start number ignored (#1118).

    New findings (no open issue)¶

    • F1 — design doc claims r16's agenda "keeps 1–4"; on screen it reads 1, 1, 1, 1 (TC-MD016, all EPs). docs/design/markdown-parser.md §"Fixed" lists "r16's agenda keeps 1–4" among the fixed items. The AST nests correctly, but the emitter splits the numbered list at each nested bullet run (#1072), so the Doc restarts at 1. The claim describes the parser output, not the Doc.
    • F2 — adjacent separate Markdown lists render as one Docs list (LM-01, LM-07, LX-05). Repro: _to_doc_requests("- a\n- b\n\n* c\n* d\n", "markdown") emits one createParagraphBullets over all four items. markdown-it now emits two <ul>s, but the AST carries no list boundary, so same-type neighbours merge.
    • F3 — a list inside a blockquote gets its left border at the list indent, not the quote's, so one quote shows two offset bars (BQ-04, CT-63–65, CT-73–75, r10's release-notes quote). Content and nesting are right; the bar is drawn at each bullet paragraph's indentStart.
    • F4 — a heading as a list item's text loses its bullet (LB-08: - # Heading inside an item renders a bare Heading 1, then a one-item list). Pre-existing (LB-08 failed in the baseline too).
    • F5 — TC-MD111 LK-12's expectation is stale. It expects "the guide" to link to ./guide.md; #1120's merged fix (_storable_link_url, PR #1149) deliberately drops a scheme-less link and keeps the text. Fixed in this pass: the case text now matches #1120, and the same screenshots pass.
