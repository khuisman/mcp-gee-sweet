## Failures

**TC-R10 — Mixed cells — formulas and literals** (sheets_read shard)
Test-file defect, not a product bug: the check references B2 for `=TODAY()` but the actual fixture layout has it in A2 (Date=col A, Note=col B in "Notes & Misc"). The tool correctly differentiates formula vs. literal cells. **Action:** correct the cell reference in `docs/qa/tests/sheets_read.md`'s TC-R10 — no code change needed.

**TC-R19 — rows_to_fetch=0 clamping** (sheets_read shard)
Real bug: `rows_to_fetch=0` clamps correctly to 1 on a cold cache (`src/mcp_gee_sweet/tools/sheets/data.py:304`), but on a warm cache the truncation slice in `src/mcp_gee_sweet/cache.py:189` (`first_rows[:rows_to_fetch - 1]`) computes `0 - 1 = -1`; Python's negative-slice semantics silently drop only the last cached row instead of clamping to empty. Same input, different output depending on prior cache state. **Action:** file a GitHub issue; fix is applying the same `max(1, rows_to_fetch)` clamp on the cache-hit path in `cache.py` that `data.py` already applies on the fetch path.

## Findings (not TC failures, but worth ticketing before/shortly after release)

**`write_doc_content` clear+reinsert leaks stale `font_size`/`font_family` into new content** (docs shard, Finding 1)
Reproduced 4 times independently. Root cause: the clear+reinsert strategy never resets the final paragraph mark's `textStyle`, so a stale explicit override (e.g. from a table or fenced code block) survives a full-document rewrite and can leak into freshly-written plain paragraphs (1pt font observed). Compounding gap: `style_doc_range` has no `font_family` parameter, so there's no lightweight way to clean up contamination once it happens — only the much heavier `apply_theme(overwrite=True)` can. **Action:** file a GitHub issue.

**TC-DOC47's prescribed SVG image URL is rejected by the live Google Docs API** (docs shard, Finding 3)
Google's API itself rejects the test's SVG URI (`HttpError 400`, unsupported format) — not a product bug. A PNG at the same host works. **Action:** update the test file's prompt to a PNG/JPEG URL, no code or GitHub issue needed.

**TC-DOC47 possible over-broad `font_family` application** (docs shard, Finding 2, unconfirmed)
Visual inspection suggested the whole line may have rendered monospace, not just the `print()` code span — but this couldn't be conclusively separated from Finding 1's contamination, and `get_doc_structure` doesn't expose `font_family` to verify precisely. **Action:** no ticket yet; revisit if `font_family` exposure is added to `get_doc_structure` (or as part of investigating Finding 1).
