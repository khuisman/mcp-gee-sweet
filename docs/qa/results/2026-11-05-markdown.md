Phase 1 of the release gate: the 16 realistic documents through all eight entry points, twice.

**Result: 214/256 cells pass, and all 42 failures are on Drive's import (EP-5 to EP-7). Our converter (EP-1 to EP-4, EP-8) passes 160/160. 9 of 16 TCs pass every cell. Run 2 matches Run 1 in every cell (Rule 4).**

## Setup

- **Code under test:** `develop` `2cf72ae3`, on four main-checkout servers. Later commits to `8c865ccf` changed only `uv.lock` and docs.
- **Shards:** A `kai-oauth` TC-MD001–004, B `oauth` TC-MD005–008, C `kai-sa` TC-MD009–012, D `sa` TC-MD013–016. No lane server was used: the four main-checkout prefixes were enough.
- **Folders:** `QA-MD-2026-11-05-run1` and `-run2` under `TEST_FOLDER_ID` (256 Docs). Trashed after recording.
- **Playwright:** account check passed before the first capture. Shards held the shared mutex around each capture batch.
- **Method:** one 1400×2200 JPEG per page. EP-1 and EP-5 of Run 1 were read by eye. EP-2, 3, 4, 8 were pixel-compared with EP-1, EP-6 and 7 with EP-5, and Run 2 with Run 1, with Docs chrome, outline pane and caret column masked. Negative controls in two shards reported DIFFERENT. A pixel match can't see a link's target: targets were checked at EP-1 and EP-5 in shards A and C, and by eye elsewhere.
- **Expectations:** C7 and BQ-04 as amended for #1293 (a quoted list item's bar sits right of the quote's).

## Failures

- **F1, Drive's code blocks changed (EP-5 to EP-7).** The list D4 points to says "aren't monospace: each line becomes its own Arial paragraph". On screen each fence is now a gray rounded monospace box with syntax colors and a language label; a fence with no language, or one Drive doesn't recognize, is labeled "None", a word not in the source. Line structure holds: one 9pt paragraph per line. This matches neither C6 nor the list, so D4 makes it a FAIL. It looks like a change on Drive's side since the 2026-10-18 baseline, which recorded "not monospace"; when it changed isn't known. The list and the `upload_local_file`, `upload_local_folder` and `sync_folder` docstrings are stale either way.
- **F2, a fenced block in a list item leaves the item (EP-5 to EP-7).** The box sits at the page margin, full width, not at the item's text (C14), in TC-MD004, TC-MD006 and TC-MD009. The list continues correctly after it. The list D4 points to doesn't name this. If it's added, these TCs stop failing on F2.
- **F3, a badge disappears (TC-MD004, EP-5 to EP-7).** The SVG badge leaves an empty line, not its alt text (C16). The TC records this as a FAIL until #1113.

## Observations on our converter

No convention decided these during the run, so their cells stay ✅. The maintainer ruled that O1 and O2 get fixed before the cut, so a re-run after those fixes grades them.

- **O1, no gap between adjacent paragraphs (#1382).** Two blank-line-separated paragraphs read as one paragraph with a line break, as in r06 Troubleshooting, where "…`docker-compose.yml`." runs straight into "`pip install` fails…". Also r01, r04, r07 and r13. Drive's import leaves a gap. BR-09's "normal paragraph spacing" in Phase 2 depends on the ruling.
- **O2, bold list markers vary inside one list (#1383).** r06's step numbers 1, 2, 4 and 5 are bold and 3 is regular. A marker follows the style of the item's last run, and only step 3 ends in plain text.
- **O3, small gaps.** r15's "Hotel:" paragraph nearly touches the table above it. r16 ends in an empty second page, which is #1100.
