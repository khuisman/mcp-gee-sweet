## Rowspan emitter bugs found and fixed (TC-D187, D188)

**Fix #1 — Sort doc_cells by startIndex** (`_build_fill_requests`): After `mergeTableCells` for rowspan, the Docs API returns covered (phantom) cells last in the `tableCells` array rather than in column order. Without sorting, the mapping zip was misaligned — the real cell was skipped and the phantom was filled. Fixed by sorting `doc_cells` by `startIndex` before zipping.

**Fix #2 — Colspan-absorbed cells emit None** (`_physical_to_ast_indices`): For combined colspan+rowspan, the colspan-absorbed col remains as a physical cell post-merge (same as a rowspan phantom). Previously, absorbed cols were skipped with `continue`, producing no mapping entry, which caused the next zip pair to align against the wrong doc_cell. Fixed by appending `None` instead of skipping, keeping the mapping length aligned with physical cell count.
