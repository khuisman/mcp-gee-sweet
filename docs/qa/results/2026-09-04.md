## Failures

**TC-D18/D19/D20/D23/D24/D176 — `share_spreadsheet` broken on Shared Drives (one root cause, BUG-SS)**
Expected: share succeeds, entries land in `successes`.
Observed: every call returns `failures:[{"error":"Failed to share: File not found: <id>."}]`. Reproduced on a throwaway sheet and the real fixture.
Root cause (confirmed in source): `share_spreadsheet._share_one`'s `permissions().create()` call omits `supportsAllDrives=True` — the only permission op in `tools/drive/sharing.py` missing it (`update_permission`, `remove_permission`, `list_permissions`, `transfer_ownership`, `share_file` all have it). Since fixtures + the default `DRIVE_FOLDER_ID` are now a Shared Drive (#305), the tool fails on any file it's pointed at in this deployment. `share_file` works (functional workaround exists). One-line fix.

**TC-D124 — stale test-case assumption, not a tool bug**
`list_permissions` on the Shared-Drive fixture shows `organizer`/`fileOrganizer` roles, no `owner` (`owners: []`, correct for Shared Drive items). The TC's "expect an `owner` entry" check predates the #305 migration. Test-case fix applied (see below).

**TC-D01 — `create_spreadsheet` response has no web link**
Response is `{spreadsheetId, title, folder}`; the TC expects a web link. Siblings (`copy_file`, `create_folder`, `get_file_metadata`) do return one. Judgment call, not filed as a bug yet — see Bugs found.

**TC-D13 — stale test-case assumption**
`list_spreadsheets(default)` no longer includes the fixture spreadsheet, because the default folder now resolves to the Shared Drive *root* (`DRIVE_FOLDER_ID`) and the fixture lives in the `FOLDER_ID` *subfolder* — correct post-#305 behavior, stale TC text.

**TC-D40 — `list_files` `max_results` cache-poisoning (BUG-CACHE)**
`list_files(FOLDER_ID, max_results=2)` returned 5 on the first call (a prior default-`max_results` call's cache hit ignored the smaller limit); a subsequent small-`max_results` fetch then *stores* the truncated list, so later default-size calls get only the truncated result until `refresh_cache`. Reproduced twice. Root cause: the folder-listing cache key omits `max_results`. Affects `list_files`, `list_spreadsheets`, `list_folders` (shared cache). Silent, persistent wrong data — the most severe finding this pass.

**TC-D167 — stale `#519`-cap test premise, same class as TC-DOC80**
`export_file`'s base64-xlsx response no longer trips the (raised) `MAX_TOOL_RESPONSE_CHARS` default at this fixture's size. Not a regression; needs the same low-cap re-run method as TC-DOC80 (#678) — tracked as a follow-up, not re-run this pass (lower priority: `export_file`'s cap-check code path is exercised and passing via TC-DOC80's sibling `get_doc_content` check and unit tests).

**TC-W02 — test-prompt bug, not a tool bug**
Prompt used single-quote string delimiters in a Sheets formula (`=A2&' '&A3`); Google Sheets requires double quotes, producing `#ERROR!`. Re-run with `=A2&" "&A3` succeeded; `USER_ENTERED` mode independently confirmed. Test-file fix applied (see below).
