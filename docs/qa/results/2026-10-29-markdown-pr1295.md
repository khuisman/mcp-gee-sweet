## Findings from this round's live checks

- **F1** (send-back on PR #1295): a nested list of the other type that ends its top-level list renders its first item one level too deep. `- P` / `  - x` / `- R` / `  1. a` / `  2. b` shows **i. a** at level 2 and **b. b** at level 1 (screenshot `regression-last-nested-list.png`). With a level-0 item after it (`- Q`) it renders correctly. The same requests built from `develop`'s source, applied live, give the same result: a regression from #1072 (PR #1286), not from this PR. The outer `createParagraphBullets` range ends at the top list's own last item (`[1,3)` for `- P` / `  1. a` / `  2. b`), so the trailing sublist's phase-1 tabs are never consumed, and `_top_list_requests`' later positions assume they were.
- **F2** (#1297): `create_paragraph_bullets` on LX-11's "Paren one" (no preset, no level), in the EP-1 Doc, moves it into the Dot list as **3.** The plain, level-0 path joins the same-preset list before it, like the anchor-wrap path #1297 describes.
